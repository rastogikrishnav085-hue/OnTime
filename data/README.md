# OnTime data layout and provenance

- `raw/`: the nine original Olist CSVs, preserved unchanged. SHA-256 hashes are in `processed/raw_manifest.json`; `build_dataset.py` verifies the files are not changed during a build.
- `interim/olist_joined.csv`: one row per eligible delivered order, rebuilt from the raw Olist tables.
- `processed/ontime_model_ready.csv`: 96,470 order rows with 33 core and 37 enriched checkout-time features. `data_quality_report.json` describes row counts, dates, missing values and provenance.
- `external/holidays_brazil.csv`: public Brazilian holiday calendar used for checkout-time calendar features. It is external context, not an Olist observation.
- `synthetic/`: reproducible generated carrier scans, weather severity, hub congestion, road disruptions and strikes for the in-transit demo. These are **SIMULATED**, generated by `make_tracking_dataset.py` with a fixed seed. Some order timestamps/IDs are copied from Olist to anchor the scenario, but the scans, weather, congestion, disruptions, carriers and strikes are invented. They are excluded from checkout-model training and cannot support claims about real weather impact.

## Model evaluation

`dashboard/verified_training_report.json` and `dashboard/chronological_report.json` document the model selection, the oldest-65% train / next-15% validation / newest-20% test split, and later-month backtesting. The current enriched model's chronological ROC-AUC is about 0.717, below the 0.90 goal. The test late rate differs from training, and probability calibration drifts; do not describe the score as a guaranteed real-world probability. The test period is kept out of fitting and threshold selection.

## Live weather

The backend route `/api/weather/forecast?latitude=...&longitude=...` requests current conditions and a three-day forecast from Open-Meteo. It is operational context only, not historical Olist data and not a model feature. A provider/network failure is reported as unavailable; synthetic weather is never substituted as if live.

## Rebuild commands

From the project root in the virtual environment:

```bash
python build_dataset.py
python audit_leakage.py
python train_verified.py
python backend/add_enriched_scores.py --serve enriched
python rolling_backtest_enriched.py
python rolling_backtest_core.py
pytest -q
```

`make_tracking_dataset.py` regenerates the separate synthetic tracking companion. The production tracking API reads `data/synthetic/`; duplicate copies previously stored under `backend/app_data/tracking/` are intentionally excluded from this package. Do not merge synthetic tables into `data/raw/`.


## Separate synthetic operational benchmark
`raw/synthetic_operational_orders.csv` is a separate synthetic CSV adapted to the existing Olist table schemas and value distributions. It is not part of the original Olist dataset and must not be merged into observed raw tables without an explicit synthetic-data filter. Read `raw/SYNTHETIC_OPERATIONAL_DATA_DICTIONARY.md` for schema, provenance, target definition, and leakage controls.
